変更内容を確認し、日本語でコミットメッセージを自動生成してコミットしてください。

## 手順

### Step 1: 状態確認

1. `git status` と `git diff`（ステージ済み・未ステージ両方）を確認
2. 最近のコミットメッセージ（`git log --oneline -10`）を確認してスタイルを合わせる
3. 変更がない場合はその旨を伝えて終了

### Step 2: 秘密情報・不要コードの検出（コミット前に必ず実行）

差分（`git diff` および `git diff --cached`）に以下が含まれていないか検査する。1つでも検出した場合は**コミットを中断**し、該当箇所をユーザーに報告する：

- APIキー・トークンのパターン（`sk-`, `ghp_`, `AKIA`, 32文字以上の英数字文字列など）
- `.env` 以外にハードコードされた秘密情報（パスワード、接続文字列など）
- conflict marker の残り（`<<<<<<<`, `=======`, `>>>>>>>`）
- `TODO: remove` や一時的なデバッグコード（`fmt.Println` によるデバッグ出力など）

### Step 3: 分割コミットの判断

変更内容を分析し、以下に該当する場合は**自動的に分割コミット**を行う：

- 異なるプレフィックスに該当する変更が混在している（例: テスト追加 + バグ修正 → `test:` と `fix:` に分割）
- 異なるモジュール/パッケージにまたがる無関係な変更がある

分割方針を決定したら、各コミットを順番に実行する。

### Step 4: amendの判断

以下の条件をすべて満たす場合、`git commit --amend` を使用する：

- 直前のコミットから5分以内（`git log -1 --format=%ci` で確認）
- 直前のコミットと同じプレフィックスの変更である
- 直前のコミットがリモートにpush済みでない（`git log origin/HEAD..HEAD` で確認）

それ以外の場合は通常の新規コミットを行う。amend する場合は、変更内容に応じてメッセージを更新する（変更が小さい場合は既存メッセージを保持）。

### Step 5: 変更サマリの表示

以下のフォーマットで変更内容のサマリを表示する：

```text
変更: <N>ファイル (+<追加行数>, -<削除行数>)
  M  internal/cache/stock.go       -- TTL付きキャッシュの実装
  A  internal/cache/stock_test.go  -- キャッシュのユニットテスト
  M  go.mod                        -- 依存追加

コミット: feat: 株価キャッシュにTTLを導入
```

### Step 6: コミット実行

関連ファイルをステージングしてコミットする。コミットメッセージはheredocで渡し、改行を正しく扱う：

```bash
git commit -m "$(cat <<'EOF'
feat: 株価キャッシュにTTLを導入

Co-Authored-By: ...
EOF
)"
```

ファイルをステージする際は `git add -A` や `git add .` を避け、関連ファイルを明示的に指定する。

## コミットメッセージのルール

- **日本語**で簡潔に記述
- プレフィックスは英語の慣例に従う: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`, `ci:`
- 形式: `<prefix>: <日本語の説明>`
- 例: `feat: ユーザー認証機能を追加`, `fix: キャッシュTTLの計算を修正`
- 「なぜ」ではなく「何を」に焦点を当てる（背景・理由は PR 説明に委ねる）
- Co-Authored-By ヘッダーを末尾に付与

### PRレビュー対応のコミットメッセージ

GitHub の PR レビューコメントへの対応であっても、**「PRの修正対応」「レビュー指摘対応」など対応の文脈だけを書くのは禁止**。実際に変更した内容そのものを記述する。

- NG: `fix: PRの修正対応`, `refactor: レビュー指摘を反映`
- OK: `fix: ユーザー名のバリデーションを32文字までに制限`, `refactor: getUserById を findUserById にリネーム`

レビュー対応であることを示したい場合は、本文（body）に補足として書く。タイトルは常に「何を変更したか」で書く。

### 本文（body）の追加基準

変更ファイルが5つ以上、または差分が100行以上の場合は本文を追加する：

```text
feat: 株価キャッシュにTTLを導入

- StockRepository に TTL 5分のインメモリキャッシュレイヤーを追加
- sync.Map でキャッシュを保持し、Get 時に期限切れをチェックして削除
- ユニットテストを stock_test.go に追加（ヒット・ミス・期限切れの3ケース）

Co-Authored-By: ...
```

## 注意事項

- `.env`, credentials 等の機密ファイルはコミットしない
- 変更がない場合はその旨を伝える
- pre-commit hook が失敗した場合は `--no-verify` で回避せず、原因を修正してから再コミットする
